# Timeweb: второе приложение на melissa-tech.ru

## Задача

Отдельный деплой только для прототипов из **MelissaTech2**, без пересборки всего первого монорепо.

## Как устроен первый репозиторий (для сравнения)

Приложение **Melissa-tech.ru** выкладывает **весь репозиторий в корень** домена. Поэтому сайт открывается как `https://melissa-tech.ru/dark-detailing/`, `https://melissa-tech.ru/delaikuzov/` и т.д. — папка в репо = путь в URL.

## Два рабочих варианта для MelissaTech2

### Вариант A (рекомендуется, как монорепо №1)

1. Второе приложение привязано к домену **`melissa-tech.ru` без отдельного префикса** (тот же корень сайта, что и у первого приложения).
2. **Директория сборки:** `/` (корень репозитория).
3. Timeweb при пуше подмешивает файлы из MelissaTech2 в общий статический корень (папки `dark-detail/`, следующие прототипы — рядом).

Тогда URL прототипа: `https://melissa-tech.ru/dark-detail/` (папка `dark-detail` в репо).

### Вариант B (отдельный префикс на второе приложение)

Если в панели указан **префикс URL** `/dark-detail/` для всего второго приложения:

- при **директории сборки `/`** в браузере откроется **корневой** `index.html` репо (заглушка «Персональный доступ»), а не сайт в папке `dark-detail/`;
- нужно указать **директорию сборки:** `dark-detail` (без слэша в конце), чтобы содержимое папки отдавалось по адресу `https://melissa-tech.ru/dark-detail/`.

## Симптом «заглушка вместо сайта»

Открывается `https://melissa-tech.ru/dark-detail/`, текст как на главной «Персональный доступ», картинки по пути `/dark-detail/img/...` не грузятся (отдаётся HTML).

**Причина:** запросы на `/dark-detail/` обрабатывает **первое** приложение (или второе с неверной директорией сборки). Папки `dark-detail/` на этом деплое нет → Caddy отдаёт fallback `index.html` с корня.

**Что сделать:**

1. В приложении **MelissaTech2** → **Настройки** → **Домены**: добавить `melissa-tech.ru` (если ещё только `*.twc1.net`).
2. Выбрать **вариант A** или **B** выше и выставить **директорию сборки** соответственно.
3. Перезапустить деплой с ветки `master`.
4. Проверка: `https://melissa-tech.ru/dark-detail/img/works/hero.jpg` должен отдавать **image/jpeg**, не HTML.

## В панели Timeweb (чеклист)

1. Приложение **Статический сайт (HTML / CSS / JS)**.
2. Git: `https://github.com/NikitaErmilovv/MelissaTech2`, ветка `master`.
3. Домен `melissa-tech.ru` привязан к **этому** приложению (вариант A или B).
4. Webhook на push в `master`.

## Deploy key (для Cloud Agent)

В **Settings → Deploy keys** репозитория MelissaTech2 — отдельный ключ (на GitHub один deploy key нельзя повторно использовать в двух репо). Пуши агента — через `gh` / HTTPS.

## После привязки

Новые прототипы — отдельные папки в корне MelissaTech2, пуш только в этот репозиторий.
